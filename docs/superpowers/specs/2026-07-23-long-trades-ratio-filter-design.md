# Long Trades Ratio 筛选设计

## 目标

在 Abook 资格判断中增加可配置的多空方向平衡筛选：按筛选期计算
`long 订单数 / (long 订单数 + short 订单数)`，默认要求结果位于 `[0.4, 0.6]`，并在参数栏和 Abook 资格漏斗中展示。

## 设计

- `AnalysisRules` 新增 `min_long_trades_ratio` 和 `max_long_trades_ratio`，默认分别为 `0.4` 和 `0.6`，取值范围为 `0–1`，且最小值不能大于最大值。
- 方向比例由现有筛选期订单聚合结果计算，分母严格使用 `long_trades + short_trades`。无方向订单时比例为 `0`，因此不能通过默认区间。
- 普通 Abook 路由必须通过该比例区间；个人候选名单和新闻候选名单继续遵循当前显式加入 Abook 的覆盖语义，确认马丁硬阻断优先级不变。
- 账户选择期指标、规则回显和 Bbook 原因增加方向比例信息；比例不通过时记录 `long_trades_ratio` 选择标记，便于审计。
- 漏斗在“样本达标”之后增加“多空比例通过”阶段，展示实际区间和本步因该规则淘汰的账户数。

## 测试与验收

- 模型测试覆盖默认值、合法自定义区间、最小值大于最大值和越界输入。
- 服务测试覆盖边界值通过、区间外被路由到 Bbook、比例使用 `long + short` 作为分母，以及漏斗阶段和淘汰原因。
- 前端契约测试覆盖参数栏的两个输入、默认规则和漏斗文案/规则字段。
- 运行后端全量 pytest 和前端生产构建，确认现有功能没有回归。
